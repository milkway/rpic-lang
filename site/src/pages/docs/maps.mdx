# Maps — pic drawings as GeoJSON

A pic drawing is a plane of inches. **geopic** places that plane on the Earth
with a four-parameter similarity — an anchor, a scale in metres per inch and
a bearing — and carries every shape to longitude/latitude: boxes and circles
become polygons, lines and arrows line strings, labels points, all with their
style as [simplestyle](https://github.com/mapbox/simplestyle-spec) properties
plus a `geopic:*` namespace. The result is a standard GeoJSON
`FeatureCollection` (WGS84) that Leaflet, MapLibre, QGIS, geopandas or sf read
directly.

Nothing about the pic language changes: the placement is a few variables in
the source (or options on the call), and the same drawing still renders to
SVG, PNG and PDF as before.

## Declare where the origin is

```pic
geo_lon = -34.8711     # WGS84 position of the pic origin (0, 0)
geo_lat = -8.0631
geo_scale = 400        # metres per inch of the drawing
geo_bearing = 0        # azimuth of +y, clockwise from north (default)

dot at (0, 0) rad 0.04
B: box "Marco Zero" "Recife" wid 1.3 ht 0.5 at (1.4, 0.9) fill 0.95 class "screen"
arrow from B.sw to (0.06, 0.06) thick 1.2
```

## Geodesic geometry

Straight segments are densified in the plane before being carried to the
ellipsoid, so a long line follows the geodesic and a circle is a true circle
in metres — not in degrees.

## From Python

```python
import rpic

fc  = rpic.geo.to_geojson(src)                     # dict: a FeatureCollection
out = rpic.geo.compile(src, frame="mercator")      # {"geojson", "warnings", "registration"}
gdf = rpic.geo.to_geodataframe(src)                # geopandas, EPSG:4326 — pip install "rpiclang[geo]"

# name features the source may refer to without defining them:
fc = rpic.geo.to_geojson(
    'geo_lon = -34.8711\ngeo_lat = -8.0631\ngeo_scale = 1000\narrow from Recife to Olinda',
    features={"Recife": (-34.8711, -8.0631), "Olinda": (-34.8553, -8.0089)},
)
```

`features` also takes a GeoDataFrame indexed by name (centroid as the point,
bounds as the bbox, so `Name.n`, `Name.e` … follow its extent). Warnings are
raised as `rpic.geo.GeoWarning` and returned structured; errors are
`rpic.geo.GeoError` with `exc.info["kind"]` (`no_registration`,
`invalid_anchor`, …).

<Callout type="note">
Reproducibility is at the millimetre, not the byte: the platform's `sin`/`cos`
differ in their last bits between operating systems, and a control-point fit
can carry that into the ninth decimal of a coordinate. The repository's own
example guard compares within 1e-8°.
</Callout>

## Use it on your own map

The maps on this page are not styled by hand: the engine emits the MapLibre
style-spec layers that draw a collection — fills, solid and dashed strokes,
dots, labels and shape titles, every size **true to the ground** from the
collection's registration — and the site just adds them. Any MapLibre map can
do the same. The layers read one GeoJSON source named `pic`:

```js
import maplibregl from 'maplibre-gl';
import { ready, compileGeoJSON } from '@strategicprojects/rpic';
import { attach } from '@strategicprojects/rpic/maplibre';

await ready(undefined, { geo: true });
const { geojson, layers } = compileGeoJSON(src, { layers: true });

const map = new maplibregl.Map({ container: 'map', style: 'https://tiles.openfreemap.org/styles/positron' });
const pic = attach(map, geojson, { layers, fit: true }); // source "pic" + six layers, once loaded
// on every edit: pic.setGeoJSON(next.geojson, next.layers); pic.fitTo();
```

`@strategicprojects/rpic/maplibre` has no imports at all — no wasm, no
maplibre-gl dependency — so it costs a few kilobytes on a page that already
has MapLibre. `createGeoMap(maplibregl, container, { style, cooperativeGestures,
navigation })` builds a ready map like the ones above. With a collection from
elsewhere (the CLI, Python), `attach(map, fc)` without `layers` computes the
same ones in JS. On the command line, `rpic --geojson --maplibre map.pic`
prints `{ "geojson": …, "layers": […] }`; in Python,
`rpic.geo.maplibre_layers(fc)` or `rpic.geo.compile(src, layers=True)`.

In R the same layers will ride on a [mapgl](https://walker-data.com/mapgl/)
map — **coming in rpic-r** (`rpic_geojson()` and `rpic_maplibre_layers()` are
not released yet):

```r
fc <- rpic_geojson(src)                      # Prompt B
mapgl::maplibre(style = carto_style("positron")) |>
  mapgl::add_source("pic", fc) |>
  purrr::reduce(rpic_maplibre_layers(fc), \(m, l) mapgl::add_layer(m, l), .init = _) |>
  mapgl::fit_bounds(fc)
```

The sizing formulas and the layer table are in
[docs/geopic.md § 6](https://github.com/milkway/rpic-lang/blob/main/docs/geopic.md#6-rendering-on-maplibre).

## Frames, caps and the contract

- `geo_frame = 0` (default) is **`enu`**: a local tangent plane at the anchor,
  geodesics by Karney's algorithms (`geographiclib-rs`). `geo_frame = 1` is
  **`mercator`**: a similarity in EPSG:3857 metres, so straight lines stay
  straight on a web map.
- `geo_px = 1` reads lengths as pixels at a `view_scale` (px per inch); the
  scene's `rescale` (`.PS <width>`) is folded in automatically.
- Hostile input cannot amplify the output: 100 000 vertices per segment,
  2 000 000 per scene (warning `densification_budget`), effective scale
  ≤ 10⁹ m/in.
- Everything the GeoJSON cannot represent — gradients, typeset math, animation
  timelines — raises a structured warning, never silence.

The full contract (registration rules, kind table, property vocabulary, JSON
Schema, warnings, versioning) is
[`docs/geopic.md`](https://github.com/milkway/rpic-lang/blob/main/docs/geopic.md);
the crate is [`geopic-core`](https://crates.io/crates/geopic-core) and the
engine does not depend on it.
